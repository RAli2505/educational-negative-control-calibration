# План диагностического пересчёта для редакторской доработки

29 октября 2026 г. План записан после изучения исходного кода и инвентаризации файлов, до выполнения нового AIPW-пересчёта. Это новая диагностическая доработка после editorial screening, не историческая пререгистрация.

## Цель и сохранённый метод

Сохраняются коррекция знаков по прокси, равное усреднение контрольных оценок и MoM-формула интервала рукописи. Эталонная выборка, ridge-веса и новые методы переноса в эту доработку не включаются. Проверяются условия применимости и реальные панели, включая возможность неуспеха.

Проверки не могут наблюдать истинный confounding bias целевого реального исхода. Прохождение диагностики не доказывает сопоставимость; нарушения могут опровергать простые аргументы в её пользу.

## Источники и выявленные проблемы

OULAD: processed/student_target.parquet и daily_vle.parquet совпали по SHA-256 с архивным manifest. Обучающий набор содержит 5859 регистраций: 3132 Pass, 703 Distinction, 1068 Fail, 956 Withdrawn. Текущий uplift_oulad.py использует Y=not Withdrawn, а рукопись определяет Y=not(Fail or Withdrawn). Запуск модуля по умолчанию также задаёт window_frac=0.5 вместо first-deadline cutoff. Два источника scripts/uplift_evalue_robustness.py и uplift_pos_multiT.py отсутствуют; остались pyc. Старые численные результаты не объявляются автоматически воспроизведёнными текущим кодом.

XES: текущие generic data/splits имеют 20767 пользователей, идентификаторы с префиксом u и EdNet source-категории sprint/diagnosis/my_note; generic loader описывает EdNet. Архивные XES-команды указывают именно на generic data. Историческое происхождение архивных чисел нельзя подтвердить без хешей соответствующего XES-входа. Для нового анализа используется явно именованный оригинальный файл data/xes3g5m/XES3G5M/question_level/train_valid_sequences_quelevel.csv. Он не подменяется generic splits. Огромные overlapping test_window-файлы не используются.

В прежнем XES builder question accuracy вычислялась по всем ответам когорты, включая поздние, и отдельно по holdout. Это заменяется оценкой сложности только из early-prefix ответов development-пользователей, с применением одной и той же карты к development и holdout. Sessions определяются разрывом между соседними взаимодействиями >1800 секунд, в отличие от старого сравнения с началом последней сессии.

## OULAD: общий дизайн для исходов и контролей

- Берётся архивный train split, с признаками строго до первого дедлайна через window_frac=None.
- Исходы отдельно: not Withdrawn (согласован с текущим uplift-кодом) и successful completion=Pass/Distinction (согласован с определением рукописи).
- Контроли: declared disability; male; age at least 35; HE/Postgraduate qualification; IMD lower bound at least 50; previous attempts >0. Это новые явно записанные бинарные кодировки, согласующиеся с архивными base rates где это возможно. IMD missing отдельно учитывается в описании; для бинарного индикатора missing кодируется 0 и оговаривается.
- Общие X для всех исходов: region, studied_credits, date_registration, семь pre-deadline VLE trend features. Все шесть кандидатов в контролях исключены из X во всех анализах, чтобы не менять adjustment design между контрольными оценками и целевым исходом.
- Propensity и support mask общие. Пять group cross-fit складок по id_student; все регистрации одного человека принадлежат одной складке. SE рассчитывается по student-cluster influence sums. Новые estimates относятся к этому common-adjustment audit, а не являются молчаливой заменой старого полного X.

## XES: явно определённая новая когорта

- Из question-level train_valid source восстанавливаются последовательности по uid; padding response/timestamp=-1 удаляется. Повторы одного (uid,timestamp,question) удаляются с подсчётом; конфликты ответов учитываются отдельно. Понятия используются как первый leaf concept token, как в исходном runner; эта ограниченность фиксируется.
- Из пользователей с >=20 уникальными наблюдаемыми взаимодействиями выбираются 6000 без возвращения, seed=20260626. Формируется user-disjoint development/holdout 80/20. Это новая выборка из именованного raw source, не воспроизведение неподтверждённой старой XES-когорты.
- Окна: первые 30%, следующие 30%, последние 40% последовательности. Их зависимость от полной длины истории является дополнительной ограничивающей предпосылкой для temporal NCO и описывается в статье.
- Design A: middle accuracy >= development median. Design B2: корректная session-start regularity >= development median; minimum 4 middle sessions and 3 positive intervals.
- Y=late accuracy >= development median. Контроли — бинарные early accuracy, early ability, early activity, early concept diversity по development median.
- Общий X для Y и всех контролей — early_wrong_concepts, единственный из исходных пяти признаков, который не определяет один из четырёх контролей напрямую. Это ограниченный sensitivity design, не полное решение confounding.
- Propensity/support общие; пять складок по пользователю. Оба новых диагностических дизайна используют обычный AIPW на общем support. Уточнение до запуска после чтения исходника: прежняя B2-функция умножала AIPW-score на вес, зависящий от фактически наблюдаемого A, и не может автоматически считаться doubly robust ATO-процедурой. Поэтому старые overlap-числа не выдаются за новые оценки общего ATE. Коррекция знаков и MoM остаются исходными; изменение estimator/design явно отмечается как диагностический пересчёт. Выводы остаются наблюдательными; отсутствие скрытого confounding не доказано.

## Диагностика сопоставимости

Для каждого набора данных сохраняются: кодировка, распространённость, корреляция с прокси и целевым исходом, матрица корреляций контролей, оценка и SE, ориентация, общий support/cohort, MoM-результат.

Leave-one-control-out pseudo-target check: каждый известный нулевой контроль по очереди становится целевым; оставшиеся ориентируются относительно его development-proxy sign и образуют поправку. Сохраняются ошибка относительно нуля и MoM-интервал. Отдельно поправка из development переносится на pseudo-target control в holdout XES. Малое число контролей и малый holdout ограничивают мощность проверки; интервалы не объявляются новым валидированным total-uncertainty методом.

Проверка общей величины proxy loading по корреляциям/линейным slopes — диагностическая, не оценка истинного скрытого bias. Устойчивость к составу панели и predictive pseudo-target error показываются без отбора благоприятных контролей.

## Техническая воспроизводимость

Используется найденный Python 3.12 с pandas/pyarrow/scikit-learn/xgboost. Версии, SHA-256 входов и кода сохраняются. Старые scripts/data не редактируются, pycache отключён. Новые результаты и обезличенные аналитические таблицы записываются только внутри editorial_revision. Окончательная рукопись отделяет эти новые диагностические результаты от архивных неподтверждённых сравнений.
